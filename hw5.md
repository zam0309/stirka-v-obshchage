# Задание 5. Схема C4 и стек MVP

Проект «Барабан» - запись на стирку в общежитиях.

## Уровень 1. Контекст

![C4, уровень 1](уровень%201.png)

Пользователи:
- Студент: живёт в общежитии, бронирует машины и стирает.
- Дежурный прачечной: отмечает поломки, следит за порядком.
- Администрация общежития: платит за сервис.
- Администратор платформы: подключает общежития и выпускает QR-коды.

Система:
- Барабан: показывает статус стиральных машин, принимает брони на стирку и напоминает о них.

Внешние системы:
- Магазины приложений (App Store и Google Play).
- SMS-сервис отправляет SMS с кодом для входа.
- Сервисы push-уведомлений (Apple, Google) доставляют уведомления на телефоны.
- Платёжный сервис принимает оплату подписки.

Связи:
- Студент -> магазины приложений: скачивает приложение по QR-коду с машины.
- Студент -> барабан: смотрит статус машин, бронирует, отмечает стирку по QR-коду.
- Дежурный -> барабан: отмечает поломки и ремонт машин.
- Администрация -> барабан: оплачивает подписку.
- Администратор платформы -> Барабан: подключает общежития, создаёт QR-коды.
- Барабан -> SMS-сервис: отправляет коды входа.
- Барабан -> Сервисы push-уведомлений: отправляет напоминания о брони и конце стирки.
- Барабан -> Платёжный сервис: создаёт платёж, получает статус оплаты.

## Уровень 2. Контейнеры

![C4, уровень 2](уровень%202.png)

Студенты и дежурный работают через мобильное приложение, администрация и мы через веб-сайт, где личный кабинет. Все запросы приходят на Nginx, он передаёт их в API. API хранит всё в PostgreSQL. Всё, что должно случиться в определённое время (напоминание, конец стирки, отмена брони при неявке), делает отдельный фоновый обработчик.

Контейнеры:
- Мобильное приложение [React Native] iOS и Android: статус машин, бронь, сканер QR, отметка поломок.
- Веб-сайт [React] - личный кабинет: подключение общежитий, печать QR-кодов, оплата подписки.
- Веб-сервер [Nginx] HTTPS, отдаёт веб-сайт, пересылает запросы в API.
- API-сервер [Python, FastAPI]: вход, статусы машин, брони, лимиты и неявки, подписки.
- База данных [PostgreSQL]: пользователи, общежития, машины, брони, очередь фоновых задач.
- Фоновый обработчик [Python] - задачи по таймеру: напоминания, конец стирки, отмена брони при неявке.

Внешние системы:
- Платёжный сервис [ЮKassa]: оплата подписки.
- SMS-сервис [SMS-шлюз]: коды для входа.
- Push-уведомления [FCM / APNs]: доставляют пуши на телефоны.

Связи:
- Администрация -> Веб-сайт: оплачивает подписку [браузер].
- Администратор платформы -> Веб-сайт: подключает общежития, печатает QR-коды [браузер].
- Студент -> Мобильное приложение: бронирует, сканирует QR [iOS / Android].
- Дежурный -> Мобильное приложение: отмечает поломки.
- Веб-сайт -> Веб-сервер: запросы к API [JSON/HTTPS].
- Мобильное приложение -> Веб-сервер: запросы к API [JSON/HTTPS].
- Веб-сервер -> API-сервер: пересылает запросы [HTTP].
- API-сервер -> База данных: читает и пишет, ставит задачи [SQL].
- Фоновый обработчик -> База данных: берёт задачи, меняет брони [SQL].
- API-сервер -> Платёжный сервис: создаёт платёж, получает статус [HTTPS, webhook].
- API-сервер -> SMS-сервис: отправляет код [JSON/HTTPS].
- Фоновый обработчик -> Push-уведомления: отправляет пуши [JSON/HTTPS].
- Push-уведомления -> Мобильное приложение: доставляют пуши.

## Стек для MVP

| Контейнер | Технология | Почему |
|---|---|---|
| Мобильное приложение | React Native | Один код сразу для iOS и Android, не нужно писать два приложения. Для сканера QR и пушей есть готовые библиотеки. QR-код на машине - это обычная ссылка: если приложение установлено, она открывает эту машину, если нет - магазин приложений. |
| Веб-сайт | React | Тот же язык, что в мобильном приложении, так что обе части может вести одна команда. |
| Веб-сервер | Nginx | Принимает все запросы снаружи: держит HTTPS, отдаёт веб-сайт, и пересылает запросы в API. |
| API-сервер | Python, FastAPI | Для MVP важнее всего скорость разработки. Сервер на 4 ядра даёт 8 воркеров Gunicorn, это десятки запросов в секунду, у наснагрузка небольшая, поэтому хватает. Go понадобится, только если вырастем до сотен общежитий. |
| База данных | PostgreSQL | Данные связаны между собой (у общежития есть машины, у машин брони, у броней студенты), и нужны транзакции. Главное: уникальный индекс на «машина + начало слота». Из 50 одновременных попыток забронировать один слот база пропустит только одну. |
| Фоновый обработчик | Python + очередь в PostgreSQL | API записывает задачу в таблицу со временем выполнения, а обработчик раз в несколько секунд забирает те, время которых наступило. Если вырастем, перейдём на Redis + Celery. |

Внешние сервисы:
- Push-уведомления: Firebase Cloud Messaging. Один сервис для Android и iOS (на iOS он отправляет через APNs).
- SMS: российский SMS-шлюз, отправляет коды для входа.
- Оплата подписки: ЮKassa. О результате оплаты она сама сообщает нашему API.
